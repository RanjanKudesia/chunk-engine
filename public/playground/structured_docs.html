py-chunks API Reference

Complete reference for the py-chunks chunking library. All public functions, parameters, and output schemas.

Installation

pip install py-chunks

Requires Python 3.9 or later. The PDFium binary is bundled inside the wheel — no separate installation needed.

Core Functions

get_chunks

Unified entry point that accepts any source type and returns a list of chunk dicts.

get_chunks(
    source,
    *,
    filename=None,
    mode="default",
    window_size=3,
    overlap=1,
    sentences_per_chunk=3,
    paragraphs_per_page=15,
) -> list[dict]

The source argument is dispatched automatically:

  • str or Path — treated as a local file path
  • str starting with http:// or https:// — treated as a presigned URL
  • bytes, bytearray, or memoryview — raw document bytes (filename required)
  • object with .filename attribute — FastAPI / Starlette UploadFile
  • object with .read() method — file-like object (BytesIO, open file)

stream_chunks

Streaming equivalent of get_chunks. Returns an iterator that yields one chunk dict per step.

stream_chunks(
    source,
    *,
    filename=None,
    mode="default",
    window_size=3,
    overlap=1,
    sentences_per_chunk=3,
    paragraphs_per_page=15,
) -> Iterator[dict]

Supported formats for streaming: PDF (all 7 modes), DOCX (default and structural only), MD (all 6 modes), TXT (all 6 modes), HTML (all 6 modes), PPTX (all 7 modes).

Chunking Modes

structural (default)

One chunk per detected block element. Each element is assigned a content_type.

FormatBlock types detected
PDFheading, paragraph, table (via font-size analysis)
DOCXheading, paragraph, table, bullet_list, code_block
HTMLh1-h6, p, pre, table, ul/ol
MDheading, paragraph, code_block, table, list
TXTheading (ALL CAPS), paragraph, code, table, list

section

Groups all content under a heading into one chunk. The section ends at the next heading of equal or higher level. Sections exceeding 2000 characters are split at paragraph boundaries.

chunks = get_chunks("doc.html", mode="section")
meta = chunks[0]["metadata"]
# meta["section_heading"] -> "2. Operational Metrics"
# meta["section_level"]   -> 2
# meta["heading_path"]    -> ["API Reference", "Core Functions"]

semantic

Merges paragraphs by topic continuity using ten heuristic signals. No ML models or external dependencies required.

  1. Transition break — however, nevertheless, in contrast (always starts new chunk)
  2. Reference continuity — this, it, they, these (same referent)
  3. Elaboration — additionally, furthermore, moreover
  4. Example — for example, for instance, e.g.
  5. Cause/effect — therefore, thus, as a result
  6. Contrast continuation — although, despite, whereas
  7. Question/answer pair — previous paragraph ends with ?
  8. Definition expansion — previous is a short label ending with :
  9. Short paragraph absorption — paragraph <= 80 chars
  10. Keyword overlap — shared significant terms

sliding_window

Overlapping windows of N blocks. Useful for RAG pipelines that need context overlap.

chunks = get_chunks("doc.html", mode="sliding_window", window_size=4, overlap=1)
meta = chunks[0]["metadata"]
# meta["window_index"]     -> 0
# meta["paragraph_range"]  -> [0, 3]
# meta["window_size"]      -> 4
# meta["overlap"]          -> 1

sentence

N sentences per chunk. Sentence boundaries detected without NLP using punctuation rules. Handles common abbreviations: Mr. Dr. vs. etc.

chunks = get_chunks("doc.html", mode="sentence", sentences_per_chunk=2)
meta = chunks[0]["metadata"]
# meta["actual_sentence_count"]  -> 2
# meta["source_paragraph_index"] -> 0

page_aware

Groups blocks by heading boundary (primary) or paragraph count (fallback). For HTML the heading boundary is an explicit h1-h6 tag. For TXT and MD it is a detected heading. For PPTX each slide is one page.

chunks = get_chunks("doc.html", mode="page_aware", paragraphs_per_page=10)
meta = chunks[0]["metadata"]
# meta["page_break_type"] -> "heading_boundary" or "estimated"
# meta["paragraph_count"] -> 7

Output Schema

Every chunk dict has exactly three keys regardless of format or mode:

KeyTypeDescription
contentstrExtracted text
content_typestrClassification (see below)
metadatadictFormat and mode-specific fields

content_type values

  • heading — section heading
  • plain_paragraph — regular prose
  • bullet_list — unordered or numbered list
  • table — tabular data
  • code_block — code or preformatted text
  • long_single_paragraph — paragraph > 900 characters
  • short_disconnected_paragraph — paragraph < 90 characters
  • section — heading-scoped grouped content
  • semantic — topic-continuity grouped content
  • sliding_window — overlapping window
  • sentence — sentence-count group
  • page_aware — page boundary group

Error Handling

All functions raise descriptive exceptions with clear messages.

ExceptionCondition
FileNotFoundErrorPath does not exist
ValueErrorUnsupported extension, invalid mode, bad parameter
TypeErrorUnsupported source type
RuntimeErrorRust-level failure (e.g. no extractable text in PDF)
NotImplementedErrorStreaming for an unsupported format
